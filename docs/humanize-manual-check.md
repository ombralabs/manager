# Очеловечивание ввода (этап Э5 движка). Сценарий ручной проверки

Около 35 минут: раздел «Очеловечивание» в редакторе профиля, почерк профиля и его сброс, горячая клавиша «Вставить как человек» и её отмена, флаги движка, клон, архив и Local API (`ombra.humanize`).

Нужны:
- Mac на Apple Silicon с macOS 14 или новее; Rust (cargo 1.90+), Node 22.12 или новее;
- сборка движка с поддержкой humanize, выбранная в «Настройки» → «Браузер»;
- один рабочий прокси (как в сценариях этапов 2 и 3);
- источник ввода «Русская» или «Русская – ПК» — шаг 4 проверяет горячую клавишу и в нём.

Результат каждого шага отмечайте в строке «Результат» (☐ → ☒). В заметку — цифры, тексты ошибок и всё, что выглядело не так.

## 0. Подготовка (5 минут)

```bash
npm ci
npm run tauri dev
```

Профили, созданные до обновления, получили очеловечивание при первом запуске новой версии (миграция 008): включено, у каждого свой почерк.

## 1. Новый профиль (3 минуты)

1. «Новый профиль» → вкладка «Очеловечивание»: «Вводить как человек» включено, «Темп» — «Обычный», «Блокировать мою мышь и клавиатуру во время автоматизации» включено, «Горячая клавиша «Вставить как человек»» — «Не задана»; в «Почерк профиля» — «Почерк появится после сохранения профиля».
2. Имя, прокси → «Создать профиль» → открыть профиль снова → «Очеловечивание»: в «Почерк профиля» пять строк — скорость набора (зн/мин), опечатки, удержание клавиши, движения мыши, прокрутка («Тачпад» или «Колесо мыши»). Запишите скорость набора.

Результат: ☐ прошло ☐ нет · заметка (скорость набора):

## 2. Сброс персоны (2 минуты)

«Сбросить персону» → диалог «Сбросить персону профиля?» с предупреждением, что почерк изменится → «Сбросить персону»: уведомление «Персона профиля сброшена», строки почерка другие (скорость набора не та, что в шаге 1). «Отмена» в диалоге ничего не меняет.

Результат: ☐ прошло ☐ нет · заметка:

## 3. Горячая клавиша (2 минуты)

1. Щелчок в поле горячей клавиши, нажать ⌃⌥V (Control+Option+V): в поле `Ctrl+Alt+V`. Нажатие одной буквы, одного модификатора, сочетания с ⌘ (⌘⇧V) или с одним ⇧ (⇧V) поле не меняет — подсказка под полем говорит почему; Backspace — снова «Не задана».
2. Задать ⌃⌥V → «Сохранить». В Терминале: `curl -s "http://127.0.0.1:45678/api/v2/browser-profile/list?limit=100" | python3 -m json.tool | grep -A6 '"humanize"'` — у профиля `"paste_key": "Ctrl+Alt+V"` и `seed` строкой.

Результат: ☐ прошло ☐ нет · заметка:

## 4. «Вставить как человек» и её отмена (7 минут)

1. ▶ профиль. В его окне открыть страницу с полями, например `data:text/html,<input id=a size=60><br><br><textarea id=b cols=60 rows=6></textarea>`.
2. В любом другом приложении скопировать абзац текста (3–4 строки). Щелчок в `textarea` окна профиля → ⌃⌥V: текст набирается по буквам, с паузами и изредка исправленными опечатками. Правый щелчок в поле → в меню есть «Paste as a Person».
3. Источник ввода «Русская» (или «Русская – ПК») → снова ⌃⌥V в пустом поле: набор идёт так же (горячая клавиша — по физической клавише V, решение D53).
4. Во время набора щёлкнуть мышью в поле `input`: набор останавливается сразу, в `input` попадает не больше одной буквы (решение D51). Ещё раз ⌃⌥V и во время набора — ⌘Tab в другое приложение: набор тоже останавливается. Esc во время набора останавливает его, и в поле Esc не попадает.
5. Щелчок внутри того же поля во время набора набор не останавливает: каретка переносится, текст допечатывается.
6. Скопировать текст длиннее 500 символов → ⌃⌥V: текст появляется сразу, как от ⌘V (решение D50).

Результат: ☐ прошло ☐ нет · заметка:

## 5. Автоматизация и блокировка (6 минут)

Скрипт Puppeteer ниже запускает профиль через Local API, щёлкает в поле, печатает 176 латинских символов (`page.type`: каждый символ — нажатие клавиши), трижды нажимает кнопку, печатает время ввода и ждёт 30 с, потом закрывает браузер. Пример AdsPower из сценария этапа 2 здесь не годится: он ничего не вводит, а очеловечивание, рамка и блокировка начинаются с первой команды ввода сессии. «Требовать ключ API» выключен, как по умолчанию.

1. **Скрипт с вводом.** Id профиля из шага 1 (№ — колонка «№» списка):

```bash
curl -s "http://127.0.0.1:45678/api/v1/user/list?serial_number=<№>"
```

   В ответе `"user_id":"…"` — это id. Затем в корне репозитория, подставив id:

```bash
REPO=$(pwd)
WORK=$(mktemp -d)
PROFILE_ID=<user_id>
cat > "$WORK/humanize-check.js" <<'JS'
// Ручная проверка Э5: щелчок, 176 символов клавишами и три щелчка по кнопке через Local API.
const puppeteer = require('puppeteer-core');
const [api, id] = process.argv.slice(2);
const TEXT = 'The profile types this paragraph through the Local API. Every letter is a key press of its own, ' +
  'so with humanized input it goes in at the speed of a person and not all at once.';
const PAGE = '<textarea id="t" cols="70" rows="5"></textarea><p>' +
  '<button id="b" onclick="this.textContent = Number(this.textContent) + 1">0</button>';
(async () => {
  const started = await (await fetch(`${api}/api/v1/browser/start?user_id=${id}`)).json();
  if (started.code !== 0) throw new Error(JSON.stringify(started));
  const browser = await puppeteer.connect({ browserWSEndpoint: started.data.ws.puppeteer, defaultViewport: null });
  const page = await browser.newPage();
  await page.goto('data:text/html,' + encodeURIComponent(PAGE));
  const t0 = Date.now();
  await page.click('#t');
  await page.type('#t', TEXT);
  for (let i = 0; i < 3; i++) await page.click('#b');
  console.log(`ввод: ${((Date.now() - t0) / 1000).toFixed(1)} с, ${TEXT.length} символов`);
  // Фокус — в поле: буквы, набранные в паузе, проверяют блокировку клавиш, а не только мыши.
  await page.focus('#t');
  console.log('пауза 30 с: щёлкните в поле и наберите несколько букв');
  await new Promise((resolve) => setTimeout(resolve, 30000));
  await browser.close();
})().catch((err) => { console.error(err); process.exit(1); });
JS
node --check "$WORK/humanize-check.js"
(cd "$WORK" && NODE_PATH="$REPO/node_modules" node humanize-check.js http://127.0.0.1:45678 "$PROFILE_ID")
```

   - Ожидание:
     - открывается окно профиля (уже открытое после шага 4 — используется оно) с новой вкладкой; с первым щелчком скрипта окно профиля в рамке;
     - буквы появляются в поле по одной, с паузами, кнопка досчитывает до 3; скрипт печатает `ввод: … с` — десятки секунд;
     - во время ввода и паузы ваши щелчки и клавиши в окне профиля до страницы не доходят: буквы, набранные в паузе, в поле не появляются;
     - после паузы окно закрывается, профиль — «Остановлен».
2. **Без блокировки.** В профиле выключить «Блокировать мою мышь и клавиатуру…» → «Сохранить» → снова последняя команда (`(cd "$WORK" && …)`):
   - Ожидание: рамки нет; в паузе щелчок в поле и несколько букв — буквы появляются в поле.
   - Затем включить блокировку обратно и сохранить.

Результат: ☐ прошло ☐ нет · заметка (время ввода):

## 7. Клон и архив (4 минуты)

1. Меню строки → «Клонировать»: у копии на вкладке «Очеловечивание» те же темп, блокировка и клавиша, а почерк другой.
2. Меню строки → «Экспорт архива…», затем «Импорт» → «Архив профиля…» → этот файл: у импортированного профиля тот же почерк, что у исходного (строки совпадают), и те же настройки.

## 8. Local API (3 минуты)

```bash
ID=<id профиля>
curl -s -X POST http://127.0.0.1:45678/api/v2/browser-profile/update -H 'Content-Type: application/json' \
  -d "{\"profile_id\":\"$ID\",\"ombra\":{\"humanize\":{\"preset\":\"careful\"}}}"
curl -s -X POST http://127.0.0.1:45678/api/v2/browser-profile/update -H 'Content-Type: application/json' \
  -d "{\"profile_id\":\"$ID\",\"ombra\":{\"humanize\":{\"paste_key\":\"V\"}}}"
```

Первый ответ — `"code":0`, в редакторе профиля темп «Осторожный». Второй — `"code":-1` с `ombra.humanize.paste_key` в `msg`, профиль не изменился.

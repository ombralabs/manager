# Командная строка автоматизации

`ombra flow` — команды автоматизации того же приложения Ombra. Команда поднимает своё ядро без окна и работает рядом с открытым окном Ombra на той же папке данных: окно закрывать не нужно. Задачи команды пишутся в базу; свои браузеры команда гасит, когда заканчивается.

## Где команда

Исполняемый файл лежит внутри приложения:

    /Applications/Ombra.app/Contents/MacOS/ombra

Имя файла проверьте командой `ls /Applications/Ombra.app/Contents/MacOS/`: если там другое имя, подставьте его в путь и псевдоним ниже. При разработке — `src-tauri/target/debug/ombra`. В систему команда не устанавливается; удобнее псевдоним в `~/.zshrc`:

    alias ombra='/Applications/Ombra.app/Contents/MacOS/ombra'

Справка: `ombra flow --help`, по команде — `ombra flow run --help`.

## Команды

| Команда | Что делает |
| --- | --- |
| `ombra flow run <файл.json \| id \| имя> (--profile … \| --serial … \| --group …)` | Создаёт задачу и выполняет её пакет |
| `ombra flow retry <task_id> [--failed]` | Новый пакет задачи: все профили или только упавшие |
| `ombra flow validate <файл.json>` | Проверяет процесс |
| `ombra flow list` | Процессы базы |
| `ombra flow import <файл.json>` | Создаёт процесс из файла, печатает id |
| `ombra flow export <id> [файл.json]` | Выгружает процесс с подпроцессами |

Флаги `run`: `--set имя=значение` (повторяется), `--data строки.csv|.xlsx|.json`, `--distribution queue|per_profile`, `--threads N` (1–100, по умолчанию 1), `--order ordered|random`, `--missing-row skip|random`, `--name <имя задачи>`, `--json`. У `run`, `retry`, `validate`, `list` есть `--json`: итог — JSON в stdout, ход — строки в stderr.

## Распределение работы

В форме новой задачи явно выбирается «Общая очередь» (по умолчанию) или «На каждом профиле». В CLI прежний режим сохраняется по умолчанию: `--distribution per_profile`.

`--distribution queue` — свободный профиль получает следующую строку таблицы и выполняет процесс с её параметрами. Закончив, он возвращается в пул. Например, 3 профиля и 100 уникальных строк обработают все 100 заданий, максимум по 3 одновременно. Без таблицы общий набор параметров считается одним заданием: процесс выполнится на одном из выбранных профилей.

Повторы убираются по первой найденной колонке `url`, `search_url`, `offer_url` или `link`; значения должны быть непустыми строками, сравниваются без пробелов по краям. Если колонки ссылок нет, сравнивается вся строка. При совпадении ссылки сохраняется первая строка. Колонки `serial_number` и `acc_id` в очереди не привязывают задания к профилям. Предпросмотр показывает число уникальных заданий и удалённых повторов.

Готовность хранится в базе по заданию. `retry` продолжает незавершённую очередь; `retry --failed` повторяет только задания с неудачной или прерванной попыткой. Успешные задания не повторяются даже после перезапуска приложения. Каждое задание и назначенный ему профиль видны в журнале; общий прогресс отображается в списке задач. «Отменить ожидающие» даёт завершиться текущим заданиям и отменяет остальные; «Стоп» прерывает и текущие.

    ombra flow run <процесс> --serial 1,2,3 --distribution queue \
      --data links.csv --threads 3 --json

Колонки таблицы должны задавать используемые процессом параметры. Для процесса Циан колонка `search_url` задаёт отдельную выдачу на задание. Разбиение одной выдачи на объявления определяется самим процессом; очередь задач не извлекает ссылки со страниц автоматически.

## Параметры и таблица

Значение переменной на профиле складывается слоями: умолчание процесса → `--set` → строка таблицы. Строка находит профиль по колонке `serial_number` или `acc_id`; без них i-я строка достаётся i-му профилю в порядке выбора (`--profile`, `--serial` или группа по возрастанию номера) — так же при `--order random` и при повторе. Колонка без объявленной переменной становится переменной-строкой. CSV — UTF-8, первая строка — имена колонок; разделитель — запятая или точка с запятой (Excel). В Excel сохраняйте таблицу как «CSV UTF-8»: обычный «CSV» с русской локалью — в другой кодировке, команда его не примет. Номер строки в ошибках таблицы считается среди строк данных: первая строка после заголовка — строка 1.

Нет строки для профиля: `--missing-row skip` (по умолчанию) — запуск «Пропущен», `random` — случайная строка.

## Секреты

Пароли и токены передавайте таблицей (`--data`) и подставляйте в узлы как `${pass}`. `--set` — для несекретных значений: командная строка остаётся в истории оболочки (`~/.zsh_history`) и видна другим программам в списке процессов (`ps`). Журнал и ход в stderr пишут поля узлов как они записаны в процессе: пароль, вписанный прямо в поле узла, окажется в журнале — так же, как он уже лежит в самом процессе и его экспорте. `password` — системная переменная (пароль профиля), колонкой таблицы она быть не может.

## Коды выхода

| Код | Когда |
| --- | --- |
| 0 | Все запуски «Готово»; `validate` — ошибок нет; повторять нечего |
| 1 | Есть «Ошибка», «Отменён» или «Пропущен»; `validate` — есть ошибки |
| 2 | Ошибка аргументов, процесса, параметров, таблицы или профилей — до первого браузера |
| 3 | Ombra недоступна: ядро не открылось или нет движка |
| 130 | Прерван сигналом |

Ctrl+C (а также SIGTERM, SIGHUP) — «Стоп»: запуски в очереди отменяются, идущие выполняют действия «после задачи». Второй Ctrl+C гасит браузеры сразу. Команда, запущенная через `nohup ombra flow run … &`, при закрытии терминала не останавливается.

## Рядом с окном Ombra

Профиль, открытый в окне Ombra или в другой команде, команда не трогает: запуск на нём — «Ошибка: профиль открыт в другом процессе Ombra». Браузеры команды окно видит остановленными, пока команда работает, но удалить, очистить или архивировать такой профиль окно не даст («папка профиля занята другим процессом»), а импорт движка, пока браузеры команды работают, отказывает: «сначала остановите все профили». Прокси, через который работает профиль окна или другой команды, команда не берёт (и наоборот): закреплённый прокси заменяется свободным, свободных нет — «нет свободных включённых прокси»; занятый прокси нельзя удалить. Потоков больше лимита запущенных профилей (Настройки, по умолчанию 20) — пакет идёт по лимиту.

## Пример

`tools/flows/examples/login-csv.json` — вход с логином и паролем из таблицы `login-csv.csv`:

    ombra flow run tools/flows/examples/login-csv.json --serial 1,2,3 \
      --data tools/flows/examples/login-csv.csv --threads 3 --json

Результат каждого профиля — переменная `greeting` в `exported`, снимок — в папке `files_dir`.

Умолчание `site` (`http://flow.ombra.test`) — адрес тестовой страницы входа: он открывается только в живых тестах Ombra. Для своего сайта добавьте `--set site=<адрес>`: на нём должна быть страница `/login` с такой же формой (поля `#user`, `#pass`, кнопка `#go`, приветствие `#hello`), иначе все запуски закончатся ошибкой. Для другой формы поменяйте селекторы в копии процесса.

## Реальный обход Циан

`tools/flows/examples/cian.json` — готовый процесс по образцу [парсера A-Parser](https://a-parser.com/resources/452/): выдача с фильтрами → уникальные ссылки → карточки → таблица. Его можно импортировать кнопкой «Импорт» в разделе «Автоматизация → Процессы» или командой:

    ombra flow import tools/flows/examples/cian.json

Для первого прогона выберите профиль с рабочим прокси. По умолчанию процесс читает одну страницу московской выдачи и три объявления. Параметр `search_url` — ваша ссылка `/cat.php` с фильтрами, `page_limit` — предел страниц, `offer_limit` — общий предел объявлений, `pause_ms` — пауза после перехода. В редакторе эти параметры находятся в узле Start; при запуске задачи — в параметрах процесса.

    ombra flow run tools/flows/examples/cian.json --serial 1 \
      --set page_limit=1 --set offer_limit=3 --json

Таблица `cian-<acc_id>[-<task_id>].xlsx` находится в папке файлов запуска. В ней ссылка, категория, заголовок, цена в рублях, адрес, даты создания и публикации, описание, ссылки на фотографии, автор, доступные телефоны и статус сессии. Те же строки доступны в `exported.offers`, сводка — в `exported.summary`. Контакты, которые сайт не отдал странице, остаются пустыми. Проверка доступа или недоступная карточка останавливает процесс; уже записанные строки таблицы сохраняются.

Для проверки входа сначала откройте этот профиль, войдите в Циан вручную и закройте браузер профиля. Затем запустите процесс с `require_login=true`: он продолжит сбор только при подтверждённой авторизованной сессии. Без этого параметра гостевая сессия допустима и отмечается как `guest`; неизвестный статус — `unknown`. После завершения процесс закрывает запущенный им браузер, в том числе при отладке; таблица и журнал остаются в папке файлов запуска.

Исходник примера — `tools/flows/cian.mjs`; после его правки обновите JSON командой `node tools/flows/cian.mjs`. Отдельная проверка на настоящем Циан запускает временный профиль и сохраняет результат в `target/acceptance/cian/native/`:

    cd src-tauri
    cargo test --lib cian_real_site -- --ignored --nocapture
